# macOS 独立虚拟屏与窗口自动路由

在 macOS 上，`idis` 支持在**不接入任何外部设备、也不开启视频编码**的情况下创建临时虚拟显示器，并配合窗口自动路由规则快速管理或隐藏桌面窗口（例如将录音/会议悬浮控件自动移至虚拟屏）。

---

## 1. 临时独立虚拟屏

- **零编码开销**：仅通过系统虚拟显示器接口创建屏幕，不启动 ScreenCaptureKit 采集与 VideoToolbox 编码，几乎不消耗 CPU/GPU 资源。
- **数量与生命周期**：单次会话最多创建 **4 块** 临时虚拟屏；仅存活于当前 `idis` 进程生命周期内，不会写入持久化配置，进程退出时自动销毁释放。
- **管理方式**：在 Web 管理端「虚拟屏与窗口路由」卡片中输入名称与分辨率（默认 `1280×720`）即可一键创建或移除；创建后可在 macOS「系统设置 → 显示器」中自由调整相对位置。

---

## 2. 桌面窗口列表与一键移动

- 管理端支持实时刷新当前桌面窗口列表，并自动识别常规应用窗口与**悬浮控件 / 置顶小窗**（标注「悬浮窗」徽章）。
- 对任意窗口可选择目标屏幕（物理屏、临时虚拟屏或扩展屏）与布局方式一键移动：
  - **保持原尺寸（`keep_size`）**：将窗口完整移入目标屏幕并保持原大小。
  - **铺满目标屏（`fill_screen`）**：移动并缩放窗口以铺满目标屏幕工作区。

---

## 3. 持久化窗口自动路由规则（`window_rules`）

你可以将常用路由配置保存为持久化规则（存储在 `~/.config/idis.yaml` 的 `window_rules` 字段中），当匹配窗口出现时由后台自动移至目标屏幕。

### 规则匹配条件
- **应用名（`app_name`）**：不区分大小写的包含匹配。
- **Bundle ID（`bundle_id`）**：不区分大小写的精确匹配。
- **窗口标题关键字（`title_contains`）**：可选，不区分大小写的包含匹配。
- **仅匹配悬浮窗（`floating_only`）**：开启后**仅移动该应用的悬浮置顶小窗**，绝不干扰同一应用的普通主窗口。

### 目标屏幕类型（`target.kind`）
- `any_virtual`：优先移至任意已创建的临时独立虚拟屏
- `virtual_name`：移至指定名称的临时独立虚拟屏
- `web_screen`：移至独立网页扩展屏
- `display`（配 `display_id`）：移至指定物理副屏或 Windows 虚拟显示器驱动屏幕
- `any_ipad` / `device`：移至已连接的传统扩展屏设备
- `main_display`：移回主机主屏幕

### 示例配置（`~/.config/idis.yaml`）

```yaml
window_rules:
  - id: hide-recording-overlay
    enabled: true
    app_name: "MeetingApp"
    bundle_id: ""
    title_contains: ""
    floating_only: true
    target:
      kind: any_virtual
    layout: keep_size
```

### 防“抢窗口”去重机制
每条规则对同一个窗口 ID 在该窗口存活期间仅自动执行一次；如果你手动把窗口拖回主屏幕，后台不会反复强行拉回。如需重新触发，可在管理端点击「立即执行全部规则」。

---

## 4. 权限与平台说明

- **macOS 权限要求**：移动其他应用窗口依赖 macOS 辅助功能（Accessibility）权限，请在 **系统设置 → 隐私与安全性 → 辅助功能** 中授权运行 `idis` 的程序。
- **Windows 支持**：原生支持桌面窗口列表、置顶悬浮窗识别（`WS_EX_TOPMOST`）、多屏一键挪窗与持久化 `window_rules` 自动归位（可与物理副屏或第三方虚拟显示器驱动搭配使用；如目标应用以管理员权限运行，请以管理员身份运行 `idis`）。
- **Linux**：当前窗口路由与独立临时虚拟屏暂不支持，访问管理界面时会自动显示提示，不影响网页扩展屏等核心功能。
